# AppCompiler

> Converts natural language product descriptions into structured, validated, executable app configuration JSON via a 4-stage AI pipeline.

## Architecture

```
User Prompt
  → [Stage 1: Intent Extraction]   — goal, entities, roles, features, constraints
  → [Stage 2: System Design]        — pages, API endpoints, DB tables, auth rules
  → [Stage 3: Schema Generation]    — full uiSchema + apiSchema + dbSchema + authSchema
  → [Stage 4: Validation + Repair]  — cross-layer checks, targeted auto-repair
  → Final JSON
```

## Why Multi-Stage?

Single-prompt approaches suffer from hallucination cascade — one bad inference corrupts everything downstream. The multi-stage compiler approach:

| Stage | Role | Analogy |
|-------|------|---------|
| 1 — Intent | Parse raw text into structured intent | Lexer |
| 2 — Design | Architect system components | Parser |
| 3 — Schema | Generate full cross-consistent schema | Semantic analysis |
| 4 — Validate | Check + repair cross-layer issues | Linker/type-checker |

## Setup

### Requirements

- Python 3.10+
- A free [Groq API key](https://console.groq.com/) (no credit card needed)

### Install & Run

```bash
cd backend
pip install -r requirements.txt
```

Edit `backend/.env` and add your key:
```
GROQ_API_KEY=gsk_your_key_here
```

Start the server:
```bash
uvicorn app:app --reload --port 8000
```

Open `frontend/index.html` in your browser.

## Evaluation

Run the evaluation suite against 20 prompts (10 real product prompts + 10 edge cases):

```bash
cd backend
python evaluator.py
```

Results saved to `evaluation_results.json` with:
- Success rate
- Average latency per prompt
- Retry count
- Failure type breakdown

## Design Decisions

### Determinism
- Temperature `0.2` — near-deterministic, consistent structure across runs
- Strict "return ONLY valid JSON" prompt instructions
- JSON extraction with triple-fallback: direct parse → markdown block → brace extraction

### Repair Strategy
Stage 4 performs **targeted repair** — not full retry. It identifies specific inconsistencies (missing keys, broken table references, unknown auth roles) and asks the model to fix only those issues. This is faster, cheaper, and avoids re-introducing new errors.

### Model Choice
`llama-3.3-70b-versatile` on Groq's free tier:
- ~3–5s per stage
- Excellent JSON instruction-following
- ~5,000 tokens total per request ≈ $0.0003 on paid tier (free on free tier)

## Deployment

### Backend → Render.com (free, no credit card)

1. Push this repo to GitHub
2. [render.com](https://render.com) → New → Web Service → Connect repo
3. Settings:
   - **Root Directory:** `backend`
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `uvicorn app:app --host 0.0.0.0 --port $PORT`
4. Environment → Add: `GROQ_API_KEY = gsk_your_key`
5. Deploy → get URL like `https://appcompiler-xxxx.onrender.com`

> ⚠️ Free tier sleeps after 15 min. First request takes ~30s cold start.

**Backup → [Koyeb.com](https://koyeb.com)** (no sleep, also free)

### Frontend → Vercel

1. [vercel.com](https://vercel.com) → New Project → drag `frontend/` folder
2. After deploy, change `API_BASE` in `index.html` to your Render URL
3. Redeploy
